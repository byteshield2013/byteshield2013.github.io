<p><strong>重点摘要</strong></p>
<ul>
<li>网站突然瘫痪的真凶往往不是 DDoS，而是合法流量暴增：为数千人设计的系统，突然要同时承接数万甚至数十万名访客。</li>
<li>把 CDN 当作最前线的负载均衡器，边缘缓存可在流量抵达机房前消化 80% 以上的请求，真正穿透到后端的只剩核心动态数据。</li>
<li>搭配多原站部署，CDN 可进行地理优化路由，并透过健康检查与故障转移在秒级内切换到健康原站，使用者完全无感。</li>
<li>对直播与实时服务而言，流量调度比加大带宽更有效；网站能否撑过高峰，在架构设计阶段就已经决定。</li>
</ul>
</div>
<p>当网站突然涌入海量请求，多数企业的第一直觉通常是：「是不是遭到 DDoS 攻击了？」</p>
<p>但事实上，许多系统故障并非源于恶意攻击，而是因为原本为数千人设计的系统，突然要同时面对数万、甚至数十万名访客。举凡大型促销活动、热门赛事直播、新游戏上市，甚至是一则爆红的社群贴文，都可能在短时间内让流量瞬间冲高数倍。</p>
<p>如果所有请求都盲目集中在单一服务器或单一机房，即使没有任何恶意流量，网站依然会变慢、无法回应，甚至直接瘫痪。这也是为什么近年来越来越多企业开始重新检视流量调度与架构弹性在整体云端环境中的关键角色。</p>
<h2>网站当机的真凶，往往不是因为流量太大</h2>
<p>许多人误以为「只要拼命加开后端服务器，就能解决流量问题」。但现实是，当流量进入系统后，如何将这些请求有效分配到不同资源，才是决定服务稳定性的核心。</p>
<p>想象一间餐厅虽然请了十位服务生，但所有上门的客人都被挤在同一个柜台点餐，排队与空等依然会发生，而后方的服务生却只能干瞪眼。服务器也是如此。当部分节点负载过高、濒临崩溃，而其他节点却仍有大量闲置资源时，整体的运算效能就无法被充分发挥。</p>
<p>过去，企业依赖传统的负载均衡器（Load Balancer）来担任那名「带位经理」；但在高并发、全球化的今天，聪明的企业已经将这道防线往前推到了网络的最前端。</p>
<h2>现代架构的新解法：利用 CDN 打造最前线的负载均衡</h2>
<p>这正是近年来备受青睐的架构思维：将 <a href="/zh/services/scdn/">CDN（内容传递网络）</a>直接作为负载均衡器（CDN as Load Balancer）。</p>
<p>传统的负载均衡器只是个「派单员」，大流量来了它就往后端塞，后端服务器还是得承担所有压力。但 CDN 具备强大的边缘缓存（Edge Caching）能力。当百万流量涌入时，所有静态资源（如图片、网页样式、甚至是部分 API 回应）在最前端的 CDN 边缘节点就被拦截并直接回传了。</p>
<p>这意味着，高达 80% 以上的流量在到达你的机房之前就已经被消化完毕，真正会穿透到后端的，只剩下核心的动态数据，从源头就大幅减轻了原站的负载（Loading）。</p>
<h2>「多原站部署」与跨区调度，改变了流量管理方式</h2>
<p>在 CDN 作为负载均衡器的基础上，现代企业更进一步采用了「多原站（Multiple Origins）」的部署策略。当企业的服务同时部署在多个不同的数据中心或云端环境时，CDN 就演变成了全球流量调度总指挥。</p>
<p>当流量来自全球各地，CDN 能根据实时状况进行智慧分流：</p>
<ul>
<li><strong>地理优化路由</strong>：越南的用户自动导向越南原站，台湾的用户导向台湾原站，确保最低延迟。</li>
<li><strong>健康检查与故障转移（Failover）</strong>：当某个区域的原站不小心异常或断线，CDN 会在秒级内自动将流量切换到其他健康的原站，使用者完全无感。</li>
</ul>
<p>这也是为什么现代 Load Balancing 观念已经与网络安全融为一体。对企业而言，防敌于外固然重要，但更具价值的，是在任何异常状况发生时，服务依然能永续运作。</p>
<h2>对直播与实时服务而言，「流量调度」比加大带宽更重要</h2>
<p>许多企业在规划<a href="/zh/blog/large-live-event-infrastructure/">大型在线直播</a>时，首先想到的通常是「带宽加得够不够大？」。然而，真正影响观众观看体验的，往往是流量路由（Routing）与资源调度的能力。</p>
<p>如果部分节点负载过高，即使整体带宽仍有余裕，观众依然会遇到画面卡顿、播放失败或影音不同步等问题。对于 OTT 平台、体育赛事直播、<a href="/zh/solutions/igaming/">iGaming</a> 以及实时互动应用而言，负载均衡不只是提升效能的技术手段，而是确保服务生命线的架构核心。</p>
<p>当瞬时流量高峰来临时，能否以最快速度将使用者导向最适合的节点，往往比单纯花大钱买带宽更有效。</p>
<h2>网站能否撑过高峰，在架构设计时就已决定</h2>
<p>评估网站稳定性时，我们习惯看服务器规格多高、带宽多大。但真正决定企业能否在流量风暴中挺住的，往往是流量有没有被有效管理。</p>
<p>透过「CDN 边缘分流 + 多原站智慧调度」，企业可以在流量暴增、甚至部分原站异常时，做到让使用者「毫无察觉」。最完美的系统架构从来不是保证不发生问题，而是在问题发生时，你的客户依然能顺利畅玩、顺利下单。</p>

<h2>常见问题</h2>
<h3>网站流量突然暴增，一定是 DDoS 攻击吗？</h3>
<p>通常不是。许多系统故障来自合法流量暴增：大型促销、热门赛事直播、新游戏上市或一则爆红的社群贴文，都可能在几分钟内让流量冲高数倍。即使没有任何恶意流量，为数千人设计的系统也会被突然涌入的数万甚至数十万名访客压垮。</p>
<h3>把 CDN 当作负载均衡器，与传统负载均衡器有什么不同？</h3>
<p>传统负载均衡器只是个派单员，后端服务器仍要承担所有压力。CDN 则透过边缘缓存在最前端拦截静态资源，让 80% 以上的流量在抵达机房前就被消化，真正穿透到后端的只剩核心动态数据。</p>
<h3>多原站部署下，某个原站故障时会发生什么？</h3>
<p>CDN 会持续进行健康检查，一旦某个区域的原站异常或断线，就会在秒级内将流量切换到其他健康原站，并搭配地理优化路由，使用者在整个故障转移过程中完全无感。</p>
